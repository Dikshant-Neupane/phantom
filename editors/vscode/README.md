# Phantom for VS Code (experimental)

Phantom can store instructions in whitespace or zero-width characters, which an editor normally
hides. This extension makes them visible so a reviewer is never surprised.

## What it does

For Python files:

- **Hover** over a `#:ws:begin` / `#:zw:begin` block (highlighted) to see the instructions it decodes to.
- **Problems panel**: one warning per hidden block with its decoded text (or an error when it cannot be decoded), plus the checks of `phantom check --strict`: zero-width characters outside a `#:zw:` block, rejected invisible code points, and bidirectional controls (reported as errors, because they can make code display differently from how it runs).
- **Command** `Phantom: Show decoded hidden instructions` lists everything for the active file.
- **Syntax highlighting** for comment-encoded instructions (`#: phantom:0.1.0 event.declare(...)`), injected into the Python grammar.

It only *reads* the document. It never runs Python, Phantom or any code from the file.

Set `phantom.enable` to `false` to switch it off.

## Honest status

- Built from this repository, **not published** to the Marketplace.
- The decoding logic (`src/decode.js`) is unit-tested with `node --test` and cross-checked against the Python implementation: `test/fixtures.json` is generated by `scripts/gen_vscode_fixtures.py` from the real encoders, and the Python test-suite fails if the file is stale.
- The VS Code integration itself (`extension.js`) is tested against a small fake of the `vscode` API, not inside a real editor. Expect rough edges and please report them.
- Only Python files are analysed. It does not replace `phantom check`; it makes the same findings visible while you edit.

## Try it

```bash
cd editors/vscode
node --test                            # logic tests
code --extensionDevelopmentPath=$PWD   # opens an Extension Development Host
# or package it:
npx @vscode/vsce package               # produces phantom-vscode-0.1.0.vsix, then "Install from VSIX..."
```

Open `docs/examples/whitespace.py` or `docs/examples/unicode.py` from the repository in the development host.

## Keeping it in sync

If an encoding changes in `src/phantom/`, update `src/decode.js`, run `python scripts/gen_vscode_fixtures.py`, and commit the regenerated `test/fixtures.json`.
